# Chromium anti-fingerprint patch (Privacy Shield native engine)

Generated by an orchestrator-workers Dynamic Workflow (1 mapper + 3 writers + 3 adversarial reviewers + 1 synthesizer). Canvas farbling, WebRTC IP suppression, navigator overrides for a patched-Chromium fork — same category Brave ships in open source.

## ⚠️ Honest status (read first)
**This patch was NOT compiled.** It targets the real current Blink/Chromium file layout and signatures and was cross-checked by adversarial reviewer agents, but not built against a live tree. Expect hand-placement of hunks + fixes at first compile. Per-component compile-confidence:

- **canvas**: low — blockers: GetTopExecutionContext() on base class; Skia GetSwSkImage/SkImages::RasterFromBitmap drift; crypto::HMAC Init/Sign overloads; WebGL data/offset/pixels accessors; async blob member vs local
- **webrtc**: low — blockers: PORTALLOCATOR_* namespace webrtc:: vs cricket::; webrtc_ip_handling_policy WebString vs std::string; placeholder hunk anchors need hand-placement
- **navigator**: medium — blockers: trailing-context anchor matches (recount); platform()/userAgent() must be the declared virtuals; String::FromUTF8/empty() spelling on older branches

Shared gate: All three require the browser-side AppendExtraCommandLineSwitches plumbing (provided in flagAndSeed) or every hook is a silent no-op.

## Apply & build
Minimum: ~100 GB disk, 16–32 GB RAM (links OOM below that), depot_tools. This local PC (7.8 GB RAM) cannot link Chromium — use a cloud build VM or stronger machine.

Prerequisites and hardware (Chromium official minimums):
  * Disk: 100 GB+ free on an SSD for a Chromium checkout + one build (src alone
    ~ 30-40 GB; a full out/ dir adds 30-80 GB; Electron adds more). Budget 150 GB.
  * RAM: 16 GB minimum, 32 GB+ strongly recommended (the final link is
    memory-hungry; low RAM thrashes or OOMs). 64-bit host only.
  * CPU: a cold full build is ~2-6 h; incremental after this patch is minutes.
  * Toolchain: depot_tools on PATH; Windows -> Visual Studio 2022 with the
    "Desktop development with C++" + Windows 11 SDK; Linux -> run
    build/install-build-deps.sh; macOS -> current Xcode.
  * A checkout matching your fork's milestone (plain Chromium src, or Electron's
    src via `gclient` with electron's DEPS). The patch anchors to recent main;
    on an Electron fork check out the matching upstream Chromium revision.

Steps:
  1. Sync deps to the pinned revision (also fetches //crypto, //third_party/webrtc,
     Skia used by the patch):
       gclient sync -D
  2. From src/, apply the patch. Hook + BUILD.gn/DEPS hunks use approximate
     context and will NOT apply clean; use --recount --reject:
       git apply --recount --reject /path/to/privacy-shield-antidetect.patch
     The 6 new files apply cleanly. Then hand-place every *.rej:
       git status --porcelain | grep '\.rej$'
     Expect rejects on: base_rendering_context_2d.cc, html_canvas_element.cc,
     canvas_async_blob_creator.cc, webgl_rendering_context_base.cc,
     peer_connection_dependency_factory.cc (both blocks, at the XXX/YYY anchors),
     navigator_*.cc, features.h, features.cc, both BUILD.gn, core/DEPS.
  3. Resolve the known unverified symbols as you place hunks (see verification):
     BaseRenderingContext2D::GetTopExecutionContext(); PORTALLOCATOR_* namespace
     (webrtc:: vs cricket::) in third_party/webrtc/p2p/base/port_allocator.h;
     webrtc_ip_handling_policy type (WebString vs std::string); Skia factory
     names (GetSwSkImage / SkImages::RasterFromBitmap); crypto::HMAC overloads.
  4. Confirm gn wiring landed: core/BUILD.gn has the 4 farble+frame sources and
     deps += [ "//crypto" ]; core/DEPS has "+crypto"; peerconnection/BUILD.gn has
     the 2 policy sources.
  5. Configure:
       gn gen out/Default --args='is_debug=false is_component_build=true symbol_level=1'
     (is_component_build=true gives faster incremental link and exercises the
      MODULES_EXPORT / CORE_EXPORT annotations.)
  6. Catch dependency errors early (this is where the missing +crypto / //crypto
     surfaces if not fixed):
       gn check out/Default //third_party/blink/renderer/core:core
       gn check out/Default //third_party/blink/renderer/modules/peerconnection:peerconnection
  7. Build. Fastest inner loop is blink_tests / the two edited targets; full
     browser is `chrome` (or `electron` for an Electron fork):
       autoninja -C out/Default blink_tests
       autoninja -C out/Default chrome        # or: autoninja -C out/Default electron
  8. Smoke-test the runtime gate (feature + token both required):
       out/Default/chrome \
         --enable-features=FarbleCanvas,FarbleWebRTC,SpoofNavigator \
         --antidetect-session-token=10743920164556128377 \
         --antidetect-hw-concurrency=8 --antidetect-platform=Win32 \
         --antidetect-user-agent="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36"
     Verify: navigator.hardwareConcurrency==8, navigator.platform=="Win32",
     navigator.userAgent matches; two getImageData() reads of the same canvas are
     identical to each other but differ from a run with a different token;
     toDataURL/toBlob pixels agree with getImageData; RTCPeerConnection surfaces
     only relay (proxied TURN) candidates. Then re-launch WITHOUT the token and
     confirm every value returns to real (strict no-op).

## Verification (what was / wasn't done)
HONEST STATUS: this deliverable was NOT compiled. No Chromium/Blink checkout was
built, no `gn gen`, no `gn check`, no `autoninja`, no linker run. The working
directory is the Privacy Shield Electron app, which contains no Chromium source
to compile the patch against. Everything below is static reasoning over the
writer drafts + adversarial-reviewer corrections.

WHAT WAS CROSS-CHECKED (orchestration-level, no compiler):
  * Feature-symbol dedup: kFarbleCanvas / kFarbleWebRTC / kSpoofNavigator are now
    declared exactly once (features.h) and defined exactly once (features.cc).
    The three source patches each emitted overlapping subsets; left as-is that is
    a duplicate-symbol / ODR link error. Resolved.
  * Session-token switch coherence: the writers disagreed — canvas and webrtc
    read "myapp-session-token", navigator read "antidetect-session-token". As
    shipped that means a single browser-appended switch could gate only some
    hooks. Unified ALL readers on "antidetect-session-token" (value doubles as
    the canvas uint64 HMAC seed; webrtc/navigator use presence). Verified the
    three reader sites now use the same literal.
  * Build-graph targets point at real files: the navigator reviewer's correction
    (there is NO core/frame/BUILD.gn; frame sources live in core/BUILD.gn with a
    directory prefix) is carried into the consolidated buildGn — the 4 new
    core files are added as "farble/..." and "frame/..." in the one core list.
  * //crypto wiring: both the DEPS "+crypto" rule AND the BUILD.gn deps+=["//crypto"]
    are present (canvas reviewer's highest-confidence gn-check breaker). Treated
    as mandatory, not optional.
  * Missing browser half: all three reviewers flagged that the patch only READS
    switches. Added the AppendExtraCommandLineSwitches plumbing + config schema so
    the feature is not a silent no-op.
  * Internal call-graph consistency: hook callsites reference only methods the new
    headers declare (IsFarblingEnabled/From/PerturbPixels/PerturbImage;
    ShouldSuppressNonProxiedWebRTC; AntidetectNavigatorConfig::Get + accessors).
  * Design invariant confirmed by reading: the on-screen StaticBitmapImage
    snapshot is never mutated; getImageData farbles the aliased buffer in place,
    toDataURL/toBlob/webgl each farble an independent COPY keyed off the same
    per-(origin,session) seed -> mutually consistent within a page, differ across
    origins/sessions.

WHAT STILL REQUIRES A LIVE COMPILE (unverified; will likely need hand-fixing):
  * All 8 hook hunks use APPROXIMATE context (writers had no tree). This will not
    `git apply` clean; use --recount --reject and hand-place. Highest-risk
    anchors: peer_connection_dependency_factory.cc (XXX/YYY placeholders, middle
    policy->Config mapping paraphrased), navigator_id.cc platform() trailing
    `#if BUILDFLAG(IS_MAC)`, features.h/.cc `namespace features {` (may be the
    collapsed `namespace blink::features {`), canvas_async_blob_creator ctor shape.
  * Unverified symbols/APIs (each a potential compile break):
      - BaseRenderingContext2D::GetTopExecutionContext() existing on the BASE
        class (canvas point's single most likely break; fallback via canvas host).
      - PORTALLOCATOR_DISABLE_* namespace: webrtc:: (post-merge) vs cricket::
        (older branches) + matching PortAllocator return type.
      - webrtc_ip_handling_policy type: blink::WebString vs std::string (changes
        the RHS of block #1).
      - WebGL: destination local named `data`, `offset` type, pixels being a raw
        DOMArrayBufferView* vs MaybeShared, Host()->GetTopExecutionContext().
      - CanvasAsyncBlobCreator: whether the image member is init-list-captured
        (then perturb the member, not the local) and whether a newer
        CanvasInterventionType/noise ctor param exists to integrate with.
      - Skia drift: GetSwSkImage(), SkImages::RasterFromBitmap(),
        UnacceleratedStaticBitmapImage::Create(sk_sp<SkImage>).
      - crypto::HMAC Init/Sign raw-pointer overloads vs base::span overloads.
      - WTF String::empty()/FromUTF8 spelling on older branches.
      - Declared qualifiers: NavigatorID::platform() must be the virtual it
        overrides; NavigatorBase::userAgent() likewise (else you add an overload,
        not an override, and the hook never fires).
  * WebGL coverage is intentionally partial: only GL_UNSIGNED_BYTE readbacks are
    farbled; FLOAT/HALF_FLOAT/packed-integer readbacks pass through un-farbled, so
    a float-renderbuffer readback is still a cross-check hole (marked PLAUSIBLE by
    both writer and reviewer).
  * set_flags() block #2 relies on the allocator being pre-Initialize(); a future
    revision that recomputes flags in Initialize() would make it a no-op (block #1
    still suffices). Not a compile risk.
  * Coherence of the emitted identity tuple is a browser-side responsibility the
    patch does not enforce.

Bottom line: this is a consolidated, internally-consistent, honestly-scoped patch
set that is expected to need hand-placement and a handful of symbol fixes on a
real tree. It has NOT been shown to compile or link.
